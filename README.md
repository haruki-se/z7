# Guitar Motion Lab

**ギターの演奏の表情を、ラジコンの動きへ変換する卒業研究用プロトタイプ。**
ZOOM G3から音を入力し、強弱・アタック・発音間隔を解析して仮想車体を動かします。Windows PCとG3で試せます。車体がなくてもデモ音源・シミュレーター・実験記録を利用できます。

## Windowsで始める

1. GitHubの **Code → Download ZIP** で最新版をダウンロードし、ZIPを展開します。ファイルを個別に取得する場合は、HTMLだけでなくJS・CSS・Pythonもすべて必要です。
2. **Python 3.10以上**をインストールします（通常はPython 3の最新版）。ChromeまたはEdgeを使用してください。
3. 展開したフォルダーの **`start-windows.bat` をダブルクリック**します。ターミナルのウィンドウは開いたままにします。
4. ブラウザで `http://127.0.0.1:8000` を開きます。まず **「デモ演奏で試す」**を押してください。

手動で起動する場合は、このフォルダーでターミナルを開いて次を実行します。

```powershell
py -3 server.py
```

macOS / Linuxでは `python3 server.py` を使用します。終了はターミナルで `Ctrl+C`。別のポートを使う場合は `py -3 server.py --port 8001` とします。

**通常の使用にpipやnpmでのインストールは不要です。** 音声処理はWeb Audio / AudioWorklet、ローカルサーバーはPython標準ライブラリを使用します。HTMLの直接ダブルクリック（file://）では音声処理を開始できません。

## まず試すこと

1. **デモ演奏**を開始。強弱のある120 BPMの合成音が解析され、仮想車体が動きます。
2. **ルールA**は強く弾くほど前進。**ルールB**はアタックに合わせて左右交互に旋回し、安定した発音間隔で速度を補正します。
3. **スピーカー出力をオン**にすると音も確認できます。初期音量は20%。出力先はWindowsのサウンド設定で選びます。
4. 実験条件をメモし、**実験記録を開始 → 記録を終了 → CSV / 条件付きJSONを保存**します。
5. **全停止**または`Esc`で動作・UDP送信・ライブ出力を停止できます。「動作を再開」でシミュレーターを再開します。スピーカー出力とUDP送信は個別に再開してください。

画面は実車のセンサー値ではありません。仮想走行の軌跡は指令から計算したもので、位置・速度の単位は実車に校正されていません。感情や印象を自動で判定する機能はありません。

## G3で演奏する

1. **G3を使うWindows PC**でこのアプリを起動し、G3をUSB接続します。初代G3とG3nはUSB機能が異なります。実機の型番・OSの認識・必要な公式ドライバーを確認してください。
2. 「G3入力を開始」でブラウザのマイク使用を許可します。選ばれた入力がG3でなければ停止し、デバイス一覧からG3を選んで開始し直します。
3. 解析チャンネルを選びます。初期値は左（入力1）。右、左右平均にも切り替えられます。モノラル機器では右の選択も同じ入力になります。左右平均は逆相で打ち消すことがあります。
4. 初めは**G3のエフェクトをバイパス**。弾かない状態で「無音を2秒測って設定」を押し、設定後に「動作を再開」します。
5. 強く弾いたときのRMS表示を目安に「強く弾いた音 dBFS」を設定します。無音判定との差は6 dB以上必要です。
6. 「スピーカー出力をオン」を押すとリアルタイムで聴けます。内蔵マイクを選んだままスピーカー出力するとハウリングすることがあります。

G3のダイレクトモニターと二重に聞こえる場合はブラウザの出力をオフにしてください。ブラウザ・OS・ドライバーの遅延が残るため、Bluetoothより有線出力を推奨します。ブラウザではOSに見えている入力を使用し、ASIOドライバーを直接選択する機能はありません。クラウド上のブラウザから手元PCのUSB機器は取得できません。

## 実装済みの機能

- 低遅延設定でのステレオ音声モニター、出力音量、最大10秒の録音・再生・保存
- AudioWorkletでのRMS、ピーク、クリッピング、アタック、簡易BPM、スペクトル重心の解析
- 音量のみ / 表情を含む2種類の動作ルール、ゲート、追従速度、速度・旋回上限
- 仮想車体と走行軌跡、左右車輪への正規化指令
- 実験ログ（約20 Hz、最大12,000行）、CSVと実験条件を含むJSON
- PythonローカルサーバーからのUDP送信、PC内仮想受信機、ESP32の受信確認用スケッチ
- 入力切断・解析停止・画面非表示・通信途絶での停止、明示的な送信開始、順序番号による古い指令の拒否

音声の取得・解析はブラウザ内です。通常使用では外部サービスへの通信はありません。UDP送信を有効にした場合も、送るのは動作指令のみです。

## 車体なしでUDP通信まで試す（任意）

1つ目のターミナルで仮想受信機を起動：

```powershell
py -3 robot_simulator.py
```

通常のサーバーを終了して、2つ目のターミナルで通信先を指定：

```powershell
py -3 server.py --robot-host 127.0.0.1 --robot-port 9000
```

ブラウザを再読み込みしてデモを開始し、「UDP受信テスト / 将来のESP32接続」を開き、「指令送信を開始」を押します。**SIM / 受信応答あり**と表示され、仮想受信機のターミナルに速度と旋回指令が出れば往復通信を確認できます。

受信機を終了すると500 ms以内を目安にサーバーが送信を停止します。ブラウザ更新が350 ms以上途絶えた場合も停止します。実際の検出にはスケジューラーの遅延が加わります。送信停止後は自動再開せず、ボタンで開始し直します。

ESP32など別の機器のアドレスを指定する場合はG3等の実入力のみ送信できます。デモはPC内の受信テストに限定しています。**モータードライバーと基板が未定のため、付属ESP32スケッチは受信確認専用（DRY）で、車輪を駆動しません。** [通信仕様と受信機の説明](docs/protocol.md)を参照してください。

## 比較実験の進め方

同じフレーズ・G3設定・入力感度・出力上限で、ルールAとBを比較します。CSVには各時刻の解析値と設定・生成指令、JSONには実験メモ、音源区分、デバイス、サンプルレート、設定変更・停止イベントも含まれます。保存はブラウザからのダウンロードで、リポジトリや外部サーバーに自動送信しません。

CSVの`speed` / `turn` / `left` / `right`は**生成指令**であり実測値ではありません。`udp_armed`やACK情報も、実車がそのとおり動いたことの証明ではありません。音声録音はログとは別ファイルです。実験条件を含めて残すにはJSONも保存してください。

解析の式、停止条件、研究での評価方法は[研究用メモ](docs/research.md)に記載しています。

## 開発・検証

Python標準ライブラリとNode.js 20以上でロジック・通信を検証できます。

```powershell
node tests/analysis.test.js
py -3 -m unittest discover -s tests -p "test_*.py" -v
```

ブラウザテストは任意です。開発用にPlaywrightとChromiumを導入して実行します。

```powershell
npm install --no-save --package-lock=false playwright
npx playwright install chromium
$env:PYTHON_COMMAND = "py"
node tests/browser.mjs
```

`PYTHON_COMMAND`はPython 3の実行ファイルまたはランチャーです。`py`がない環境はPython 3の実体のパスを指定してください。既存ブラウザを使う場合は`CHROMIUM_PATH`を指定できます。テスト用ポート18765/19000を使い、モーターは動かしません。

クラウドのLinux/Chromiumで、合成信号のDSP、2ルールの動作、録音、実験データ保存、UDP往復通信と停止条件を検証しています。**Windows・G3実機での音声、物理車体、Arduinoスケッチの実機ビルドは未検証です。**
