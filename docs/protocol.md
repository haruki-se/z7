# 指令通信と受信機

通常はシミュレーターだけを使います。車体やドライバーが決まった後に、以下の受信プロトコルへ機種に合った駆動処理を接続できます。

## ブリッジ

`py -3 server.py --robot-host 192.168.1.100 --robot-port 9000`

上のIPは例です。実際の受信機のIPv4アドレスを指定してください。ブラウザはlocalhostへHTTPで指令を送り、PythonがUDPに変換します。サーバーは127.0.0.1だけにバインドし、同一オリジンからの操作を受け付けます。外部IPへのデモ送信は拒否します。ローカルサーバーは起動中の設定先を変更するAPIを提供しません。

HTTP API：`GET /api/status`、`POST /api/arm {source}`、`POST /api/command {token, seq, speed, turn}`、`POST /api/stop {token}`。armの戻り値のtokenはその送信セッションにだけ有効です。停止や通信途絶で失効し、再開時には新しいtokenを取得します。

## UDP v1

UTF-8互換ASCIIの改行区切り（1パケット1行）：

```text
G3,1,0123abcd,1,0,0.0000,0.0000\n
G3,1,0123abcd,2,1,0.2000,-0.1000\n
```

|項目|意味|
|---|---|
|G3|マーカー|
|1|プロトコルバージョン|
|0123abcd|8桁16進セッションID|
|1 / 2|単調増加する32 bit順序番号|
|0 / 1|停止 / 有効|
|speed|前進指令0〜0.6（実測速度ではない）|
|turn|旋回指令−0.6〜0.6|

新しいセッションは停止フラグかつspeed/turn=0で確立します。受信機は新セッションの非ゼロ指令や古い順序番号、不正な数値を拒否します。ブリッジは停止指令へのACKを受け取るまで走行指令を送りません。通常は約20 Hzで最新指令を送信します。

ACKは送信元IPとポートへ返します：

```text
G3ACK,1,0123abcd,2,SIM\n
```

最後の値は`SIM`（PC受信機）、`DRY`（駆動なしの受信確認）、`RUN`（将来の駆動実装用予約値）。ACKは受信の確認であってモーター動作の証明ではありません。プロトコル自体には暗号化・機器認証はなく、管理下のローカルネットワークでの試作向けです。

350 ms以上有効な指令が来ない場合、受信側の速度・旋回は0になり、同一セッションの走行再開は拒否します。新しいセッションIDで停止指令から開始し直してください。PC版の参照実装は`protocol.py`です。

## ESP32での受信確認（任意・車体未定）

`firmware/g3_receiver/g3_receiver.ino`は**受信確認専用**です。GPIOやPWMには出力しません。モータードライバーを接続しなくても、速度・旋回をシリアルモニターで確認できます。

1. Arduino IDEにArduino-ESP32のボードパッケージを導入し、手元のESP32に対応するボードを選びます。
2. `g3_receiver.ino`を開きます。
3. 同じフォルダーの`config.example.h`を`config.h`へコピーし、手元PCでWi-FiのSSID・パスワードを設定します。`config.h`はGitの対象外です。値を公開しないでください。
4. ビルドして書き込み、115200 baudのシリアルモニターでIPを確認します。
5. そのIPを`--robot-host`で指定したサーバーを起動し、G3入力から「指令送信を開始」を押します。受信機の表示は`DRY`です。

Wi-Fi未設定でもUSBシリアルで同じ形式の行を受け取れます。これは手動の受信確認用で、Web画面からのUSBシリアル送信は未実装です。

このクラウドでは基板とArduinoツールチェーンがないため、スケッチの実機ビルド・Wi-Fi接続は未検証です。モーター駆動、サーボ、電源、GPIOの割り当ては、基板とドライバーが決まった段階で追加します。タイムアウト時には、指令変数を0にするだけでなく実際のPWMを停止する必要があります。
